# CODEX 최종 개발 지시서 — NONGSHIM VINTAGE MACHINE

**이 파일이 최종 단일 지시서입니다.** 이전 버전의 CODEX_BRIEF.md(랜덤 포춘, 웰치스 매칭 제외, 잘못된 2003×카프리썬 예시 등)는 사용하지 마세요. ZIP의 실제 이미지들과 `PRODUCT_DATA.json`을 참고하여 **구동·테스트 가능한 웹앱**을 제작하세요. 글 설명, 정적 목업만 만들지 말고 앱 구현·실행 검증까지 완료할 것.

## A. 목적·디자인 (최우선)

- 이름: **NONGSHIM VINTAGE MACHINE**. 이용자가 출생연도를 입력하면, 가까운 기준연도의 농심 음료가 자판기에서 떨어지고 별도 슬롯에서 감열지 영수증이 인쇄되어, 제품별 감성 문구가 나오는 개인화 웹페이지.
- `assets/references/matte_red_vending_design.png`: 메인 디자인 방향. **무광, 빈티지 레드·크림, 절제되고 아기자기한 레트로 자판기**, 약간의 종이/인쇄 질감. `original_six_product_layout.png`: 3×2 배열과 전면부 구조 참고. 두 이미지를 그대로 페이지 배경으로 깔지 말고 DOM/CSS/SVG 컴포넌트로 재구현할 것.
- 중요: **시각적 완성도와 비례·간격·폰트·여백에 집중. 불필요한 요소나 묘사/카피를 절대 추가하지 말 것.** AI가 만든 티가 나는 흔한 카드 UI, 반짝임, 노란 강조선, 별/스파클, 유리 광택, 글로우/네온, 과도한 그림자·그라데이션, 뜬금없는 장식·스티커·이모지·부제목/설명 텍스트, 배경 일러스트, 제품에 없는 문양·글자 **전부 금지**. 단순하고 세련된 빈티지 웹디자인. 코인 투입구·동전 반환·가격/결제·우측 조작패널 제거.
- 자판기 전면 필수 요소: (1) 제목, (2) 상단 3열×2행 진열 제품 6개, (3) 출생연도 입력창 + 뽑기 버튼, (4) 작고 좁은 **빈 영수증 출력구**, (5) 별도 크고 깊은 **음료 배출구**. 출력구는 반드시 둘 다 있어야 하며 동일한 것으로 합치지 말 것. 최초에는 영수증이 나오지 않음.
- **실제 판매 제품 이미지의 원본 파일만 사용.** ZIP `assets/products`의 실제 제품 사진 파일을 `<img>`로 불러오고 로고/텍스트/색상/패키지 비율·형태를 임의 재그리기/이미지 생성/AI 리터칭/상품과 다른 대체 사진 사용 금지. 투명 배경이 필요해도 글자·색·외형은 조금도 수정하지 말 것. 원본 보존, CSS `object-fit: contain`로 표시. 6개 진열 순서는 상단 [카프리썬 오렌지 / 카프리썬 사과 / 파워오투 애플키위], 하단 [파워오투 오렌지레몬 / 오이오차 녹차 / 웰치스 그레이프].
- 원본 패키지는 재현·추정하지 말 것. 정식 공개 전 담당자가 실제 현행 판매 이미지인지 확인할 수 있도록 README에 `이미지 검수 체크리스트` 명시. 마켓플레이스 이미지를 임의 크롤링해서 오염시키지 말 것.
- 모바일 우선 반응형. 소형 휴대전화에서도 제품 6개·출생연도 입력 필드·버튼 및 두 출력구가 겹치거나 잘리지 않을 것. 세로 스크롤은 허용, 우측 가로 스크롤 금지.

## B. 사용자 플로우 — 순서 변경 금지

1. 첫 화면은 여섯 제품이 진열된 자판기. 출생연도 `YYYY` 입력 (4자리 정수, 1900~현재 연도; 적절한 오류 표시) → `뽑기` 버튼 클릭 또는 Enter.
2. 가장 가까운 기준연도 매칭 후 **정확한 제품 사진을 가진 음료가 진열대에서 아래 음료 배출구로 굴러 떨어져 가볍게 튀면서 멈추는 모션**. 단순 순간 이동 금지. 파우치/페트병/캔의 회전과 착지 반응은 무리하지 않게 차별화. 약 1~1.5초.
3. **음료 배출이 종료된 뒤** 별도의 **영수증 출력구** 안쪽에서 감열지 영수증이 아래로 천천히 출력되는 모션. 약 1.5~2초. 슬롯의 마스킹과 종이 길이 변화로 프린터처럼 보일 것. 출력 동안 메시지 전문을 먼저 보여주지 말 것.
4. 출력된 영수증을 클릭/탭하면 별도 중앙 결과 화면/모달로 확대되고 문구 전체 공개. 클릭 가능함을 과하지 않게 표시 (`영수증 확인` 같은 최소 안내만 허용).
5. `이미지 저장`을 통해 **영수증 본문 전체를 잘림 없이 PNG로 다운로드**. `다시 뽑기` 가능. 모바일 공유(Web Share API)는 지원하는 경우에만 선택적으로 제공.
6. 불필요한 중간 단계, 퀴즈, 코인 넣기, 로그인, SNS 태그 강요, 결제 UI, 효과음 강제재생, 인위적 타이핑 효과, 난잡한 플로팅 장식 금지. 전체 모션 약 3~4초 이내. 사용자의 `prefers-reduced-motion` 지원.

## D. 매칭: 다섯 기준연도 전부 지원

연도는 숫자로 관리하고 어느 해든 동작해야 함. 데이터는 `PRODUCT_DATA.json` 참고. `1995 / 1998 / 2005 / 2010 / 2014` 다섯 기준연도에 모두 동일한 **이전 출생 / 동갑 / 이후 출생** 처리 필수. 특정 연도(2005 등)만 특수 처리하지 말 것.

**기준연도-제품:**
- **1995** 웰치스 그레이프(캔). **기획용 기준연도**로 사용하되, **웰치스 소다의 국내 공식 최초 출시연도라고 단정하지 않는다**. 텍스트도 `1995년, 웰치스가 우리 곁에 찾아왔습니다.`처럼 정해진 표현 사용. 이번 캠페인의 매칭 대상에는 포함.
- **1998** 카프리썬 오렌지 / 사과. 추가 종류(사파리·오렌지망고)는 현재 패키지 원본과 선택 UI가 없으므로 임의 이미지·색상 만들어 넣지 말 것. 향후 데이터 추가 가능 구조.
- **2005** 파워오투 애플키위 / 오렌지레몬.
- **2010** 오이오차 녹차.
- **2014** 카프리썬 멀티비타민 / 오이오차 쟈스민티. **중요: 이 두 제품은 현재 ZIP에 정확한 공식 제품 사진이 포함되어 있지 않다.** 절대 다른 맛/상품의 사진을 해당 제품인 양 보여주지 마라. 해당 연도도 매칭 로직과 인트로 분기는 반드시 개발하고, 제품 이미지가 확보되기 전까지는 `2014 카프리썬 멀티비타민`처럼 **정확한 이름만 표시하는 텍스트형 결과로 안전하게 폴백**하되 음료 떨어짐 동작은 디자인에 맞춘 최소한의 이름표/실루엣 대체로 구분하고, README에 `2014 공식 제품 사진 필수 보완`으로 표시. 오이오차 쟈스민티는 아직 별도 감성 문구가 미승인 상태: **다른 제품의 감성 문구를 복제하거나 AI로 새로 지어 넣지 말고** `문구 준비 중`으로 명시. **더 나은 실무 대안:** 공식 사진/문구가 보완되기 전 데모 시 2014년은 카프리썬 멀티비타민으로 매칭하고 브랜드 공통 카프리썬 문구를 사용하며 텍스트형 배출로 표시할 것. 향후 사진 추가 시 자동 전환 구조로 구현.
- 기존 2022+ 웰치스 제로 제품은 절대 넣지 말 것.

**알고리즘:**
1. `distance = Math.abs(birthYear - releaseYear)`.
2. 다섯 출시연도 중 최소 distance 연도 선택. 연도가 동률이면 두 연도 중 **일관적인 규칙으로 무작위 선택**(혹은 출시연도가 빠른 쪽을 우선 선택하는 정책을 선택하고 README에 명시; 테스트는 결정적 주입 가능하게). 해당 기준연도의 후보 제품이 2종이면 랜덤 선택. 누락 이미지/문구가 있으면 데모에 안전한 후보 우선.
3. 입력한 출생연도와 기준연도의 앞뒤 관계에 따라 도입 **두 문장**을 자동으로 조립. 나머지 고정 문단은 변경 금지.
4. 두 자리 나이(연도 차이)는 수학적으로 `abs` 차이. 출시월과 생일 정보가 없어 만 나이가 아니라 **연도 차이 기준**으로 설명. 한글 나이 숫자('다섯 살', '두 살')로 자연스럽게 변환하되 안전한 일반 표현('5살')도 허용.
5. 출시 전에 태어난 사용자라도 결과가 가능해야 함. `n년 뒤`를 음수로 만들면 안 됨. 1995, 1998, 2005, 2010, 2014 각각 입력 연도가 동일한 경우 모두 `같은 해` 형태 사용.

**동적 두 문장 규칙 (출시연도=Y, 출생연도=B, 브랜드 이름=N):**

- **B > Y (제품이 먼저 나옴):**
  `Y년, N이/가 세상에 나왔습니다.` (브랜드별 확정 문구 우선 적용. 특히 웰치스는 `Y년, 웰치스가 우리 곁에 찾아왔습니다.`)
  `그리고 (B-Y)년 뒤, 당신의 첫 번째 하루가 시작되었죠.`
- **B < Y (이용자가 먼저 태어남):**
  `B년, 당신의 첫 번째 하루가 시작되었습니다.`
  `그리고 당신이 (Y-B)살이 되던 해, N도 우리 곁에 찾아왔죠.` (문맥과 조사 자연스럽게. 오이오차 녹차의 확정 문구는 `그리고 당신이 다섯 살이 되던 해, 오이오차 녹차도 우리 곁에 찾아왔죠.` 패턴 그대로.)
- **B === Y (동일 연도):**
  `Y년, N이/가 세상에 나왔습니다.` (웰치스는 위 확정 고유문)
  `그리고 같은 해, 당신의 첫 번째 하루도 시작되었죠.`

도입부 구성은 각 연도별로 단순 문자열 치환이 아니라 브랜드별 표현 예외와 날짜 관계를 처리할 수 있는 함수로 구현할 것. 한글 조사 처리 오류를 피하기 위해 `intro_name`, `intro_first_clause` 같은 데이터에서 직접 설정해도 됨.

### 틀리면 안 되는 실제 테스트

- **1995년생 → 웰치스 1995 (같은 해)**
- **1998년생 → 카프리썬 1998 (같은 해)**
- **2005년생 → 파워오투 2005 (같은 해)**
- **2010년생 → 오이오차 2010 (같은 해)**
- **2014년생 → 2014 출시 제품 (같은 해 / 아직 사진 폴백)**
- **2000년생 → 1998 카프리썬** (차이 2년 vs 2005 차이 5년, 카프리썬 문구의 `그리고 2년 뒤`)
- **2008년생 → 2010 오이오차 녹차** (차이 2년 vs 2005 차이 3년, `당신이 두 살이 되던 해`)
- **2003년생 → 2005 파워오투**, 1998 카프리썬이 아님 (2년 vs 5년 차이)
- **1997년생 → 1998 카프리썬**, 1995 웰치스 아님 (1년 vs 2년 차이)
- **2012년생 → 2010 or 2014 (정확한 동률)**. 타이브레이크 정책대로 동작.
- **1990년생 → 웰치스 1995**, 이용자 먼저 출생 분기.
- **2016년생 → 2014 제품**, 제품 먼저 출시 분기.

그때는 얼른 어른이 되고 싶었는데, 막상 어른이 된다는 건 생각보다 어려운 일이네요.
오늘 하루도 잘 살아내셨습니다. 내일의 당신도 응원합니다.

**도입 2문장은 D 분기에 맞게 동적으로 구현.** E2에서만 뒤 문장을 `당신도 태어났죠.`로 유지하는 브랜드별 문체 특례 허용. 현재 출시연도 매칭에서 카프리썬 예시는 **2000년생×1998년(2년 뒤)**가 정확하며 2003년생×1998년은 잘못된 예시이므로 쓰지 말 것.

### E3. 파워오투(2005)

친구들과 목이 터져라 응원하고, 목이 바짝 마를 때면 파워오투 한 모금으로 갈증을 달래던 체육대회 날.

### E4. 오이오차 녹차(2010)

2008년, 당신의 첫 번째 하루가 시작되었습니다.
그리고 당신이 두 살이 되던 해, 오이오차 녹차도 우리 곁에 찾아왔죠.
어릴 적에는 엄마 아빠가 왜 씁쓸한 녹차를 좋아하는지 이해하지 못했습니다.
그런데 신기하게도, 시간이 지날수록 예전에는 몰랐던 맛을 하나둘 알아가게 됩니다. 자란다는 건, 이해하지 못했던 부모님의 모습을 조금씩 이해하게 되는 일인지도 모르겠습니다.
오늘은 어느새 주름이 깊어진 그들의 눈을 바라보며, 그동안 미처 전하지 못했던 다정한 한마디를 건네보는 건 어떨까요?

## F. 구현 세부사항

- React + Vite + TypeScript(기존 프로젝트가 있으면 기존 스택 준수). 원본 이미지 `public/assets/products` 또는 번들 asset으로 보관. `PRODUCT_DATA.json` 기반 자료형 명시. 브랜드별 고정 문구 데이터와 intro 생성기 분리.
- UI state: `idle` → `dispensing` → `printing` → `receipt_ready` → `receipt_open` (오류/다시뽑기 포함). 사용자 중복 연타 방지, 모션 종료 후 화면 전환, 브라우저 뒤로/리사이즈에서도 깨지지 않도록.
- 음료 배출은 가능한 **실제 제품 이미지**를 이동시켜 구현. `2014`처럼 이미지 미비 시 **실제 판매 패키지를 흉내 내는 가짜 이미지 금지**, 텍스트 전용 결과로 교체하고 개발자 TODO를 남길 것.
- 영수증 png 만들 때 폰트 로딩 후 캡처, CORS 문제 없는 내부 이미지 사용, 긴 내용 잘림 방지, 모바일 Safari 포함 가능하면 검증.
- `prefers-reduced-motion`, 키보드 엔터, 영수증 키보드 접근, 모달 focus 및 닫기, 적절한 오류 처리.
- 별도 관리자 페이지/서버/DB/로그인/마케팅 분석/추적 코드 불필요. 출시연도만으로 매칭하므로 실제 달력 일자·생일 데이터도 요구하지 말 것.
